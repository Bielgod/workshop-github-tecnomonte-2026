# Workshop GitHub - TecnoMonte 2026

## Colaboração no GitHub: da Issue ao Pull Request

Bem-vindo ao workshop de Controle de Versões e Colaboração com Git, GitHub e GitLab!

O objetivo é aprender, na prática, como contribuir para um projeto colaborativo utilizando issues, forks, branches, commits, pull requests e revisões.

## Objetivo da atividade

Cada participante deverá criar uma contribuição individual em Markdown para construir um Guia Colaborativo de Git e GitHub.

Não existe um número fixo de participantes. Cada pessoa criará seu próprio arquivo na pasta `contribuicoes/`.

## Pré-requisitos

- Conta no GitHub
- GitHub Desktop instalado e autenticado
- Editor de texto
- Acesso à internet

## Passo a passo da atividade

1. Abra uma issue no repositório original descrevendo sua contribuição e os critérios de aceitação.
2. Faça um fork deste repositório para sua conta.
3. Clone o seu fork utilizando o GitHub Desktop.
4. Crie uma branch exclusiva para sua contribuição.
5. Crie um arquivo Markdown dentro da pasta `contribuicoes/`.
6. Nomeie o arquivo como `seuusuario-issue-N.md`, substituindo N pelo número da issue.
7. Escreva uma explicação simples sobre um comando ou conceito do Git.
8. Confira as alterações e faça um commit.
9. Publique sua branch no seu fork.
10. Abra um pull request direcionado à branch `main` do repositório original.
11. Relacione o pull request à issue usando `Closes #N`.
12. Revise o pull request de um colega e registre um comentário útil.
13. Responda à revisão recebida e faça os ajustes solicitados, se necessário.
14. Aguarde a conferência e a integração pelos organizadores.

## Modelo de contribuição

Crie um arquivo seguindo este exemplo:

```markdown
# git status

**Autor:** @seuusuario

## O que é?
Explique o comando ou conceito escolhido.

## Como utilizar?
Mostre um exemplo simples.

## Dica para iniciantes
Compartilhe uma dica prática.
```

## Regras de colaboração

- Crie apenas o seu próprio arquivo.
- Não altere os arquivos dos colegas.
- Utilize mensagens de commit claras.
- Relacione seu pull request à issue correspondente.
- Leia e responda aos comentários da revisão.
- Respeite as contribuições dos demais participantes.

## GitHub e GitLab

No GitHub, as alterações são propostas por meio de Pull Requests (PRs).

No GitLab, o processo equivalente utiliza Merge Requests (MRs).

As duas plataformas utilizam Git e permitem colaboração, issues, branches e controle de acesso.
